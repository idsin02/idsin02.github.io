PsExec-like remote service execution

Detect a remote service created after an admin-share or Service Control Manager action, then confirm that services.exe launches the service binary. Keep approved management workflows quiet only when every exclusion field matches.

Week goal

Connect three facts: a remote source reaches an admin share or remotely opens SCM, a service is created on the target, and services.exe starts the matching binary. Cleanup is valuable context, but it is not required to match.

Success means scenarios S1 and S2 match. S3–S8 must stay quiet.

Why this is behavior-based

PsExec commonly creates a service, but an attacker can choose another service name. The capstone follows the remote sequence and uses names and paths as context rather than the only signal.

Week 17 · Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Normalize share, service-control, service, and process events.
  2. Build precursor, service-create, and process-start sets.
  3. Join on source, target, account, and service name.
  4. Enforce five-minute and two-minute windows.
  5. Remove only exact approved tuples.

Tuning choice

The example uses a normalized table called RemoteExecEvents_CL. Map it to your workspace first. A server-only allowlist is too broad: if an approved source uses an unexpected account, service, or path, keep the event visible.

Require source + account + service name + service path. Review owners and expiry dates.

KQL answer

let CorrelationWindow = 5m;
let ExecutionWindow = 2m;
let ExactApproved = datatable(SourceDevice:string, Account:string, ServiceName:string, ServicePath:string)
[
  "SCCM-MP01", "CORP\\svc_sccm", "CcmExecUpgrade", @"C:\Windows\ccmsetup\ccmsetup.exe",
  "RMM-01", "CORP\\svc_endpoint_mgmt", "ContosoEndpointAgentUpgrade", @"C:\Program Files\Contoso Endpoint\agent-upgrade.exe",
  "BACKUP-01", "CORP\\svc_backup", "CorpBackupSnapshotSvc", @"C:\Program Files\CorpBackup\snapshot-agent.exe",
  "SUPPORT-GW01", "CORP\\svc_remote_support", "ApprovedRemoteSupportSvc", @"C:\Program Files\Approved Support\support-host.exe"
];
let Precursors = RemoteExecEvents_CL
| where (EventType == "share" and ShareName in~ ("ADMIN$", "C$"))
    or (EventType == "service_control" and Action in~ ("OpenSCManager", "CreateServiceW"))
| where SourceDevice != TargetDevice
| project SourceDevice, TargetDevice, Account, PrecursorTime=TimeGenerated, PrecursorType=EventType, ShareName, Action;
let Services = RemoteExecEvents_CL
| where EventType == "service" and Action == "create"
| project SourceDevice, TargetDevice, Account, ServiceTime=TimeGenerated, ServiceName, ServicePath
| join kind=leftanti ExactApproved on SourceDevice, Account, ServiceName, ServicePath;
let Starts = RemoteExecEvents_CL
| where EventType == "process" and Action == "start"
| where ParentProcess endswith "\\services.exe"
| project TargetDevice, ServiceName, ProcessTime=TimeGenerated, ProcessName, ParentProcess, CommandLine;
Services
| join kind=inner Precursors on SourceDevice, TargetDevice, Account
| where PrecursorTime between (ServiceTime - CorrelationWindow .. ServiceTime)
| join kind=inner Starts on TargetDevice, ServiceName
| where ProcessTime between (ServiceTime .. ServiceTime + ExecutionWindow)
| summarize arg_min(PrecursorTime, *), arg_min(ProcessTime, *) by SourceDevice, TargetDevice, Account, ServiceName, ServicePath, ServiceTime
| project ServiceTime, SourceDevice, TargetDevice, Account, PrecursorType, ShareName, ServiceName, ServicePath, ProcessName, ParentProcess, CommandLine
| order by ServiceTime desc

Analyst reasoning

Likely false positives: SCCM or other software deployment, endpoint-management agents, backup snapshot helpers, and sanctioned remote support. Confirm the management server, service account, target scope, exact service name/path, change ticket, signer/hash, and execution window. If any exact field changes, investigate rather than expanding the allowlist immediately.

CrowdStrike CQL answer

#event_simpleName=/^(SmbShareAccess|RemoteServiceControl|ServiceInstalled|ProcessRollup2)$/
| case {
    #event_simpleName=SmbShareAccess ShareName=/^(ADMIN\$|C\$)$/i
      | PrecursorHit:=1 | ServiceHit:=0 | ProcessHit:=0 | Step:="admin-share";
    #event_simpleName=RemoteServiceControl Operation=/^(OpenSCManager|CreateServiceW)$/i
      | PrecursorHit:=1 | ServiceHit:=0 | ProcessHit:=0 | Step:="service-control";
    #event_simpleName=ServiceInstalled
      | PrecursorHit:=0 | ServiceHit:=1 | ProcessHit:=0 | Step:="service-create";
    #event_simpleName=ProcessRollup2 ParentBaseFileName=/^services\.exe$/i
      | PrecursorHit:=0 | ServiceHit:=0 | ProcessHit:=1 | Step:="service-process";
    * | PrecursorHit:=0 | ServiceHit:=0 | ProcessHit:=0 | Step:="other";
  }
| not (
    (SourceHost="SCCM-MP01" UserName="CORP\\svc_sccm" ServiceName="CcmExecUpgrade" ServiceImagePath="C:\\Windows\\ccmsetup\\ccmsetup.exe") or
    (SourceHost="RMM-01" UserName="CORP\\svc_endpoint_mgmt" ServiceName="ContosoEndpointAgentUpgrade" ServiceImagePath="C:\\Program Files\\Contoso Endpoint\\agent-upgrade.exe") or
    (SourceHost="BACKUP-01" UserName="CORP\\svc_backup" ServiceName="CorpBackupSnapshotSvc" ServiceImagePath="C:\\Program Files\\CorpBackup\\snapshot-agent.exe") or
    (SourceHost="SUPPORT-GW01" UserName="CORP\\svc_remote_support" ServiceName="ApprovedRemoteSupportSvc" ServiceImagePath="C:\\Program Files\\Approved Support\\support-host.exe")
  )
| groupBy([SourceHost, ComputerName, UserName, ServiceName], function=[
    min(@timestamp, as=FirstSeen),
    max(@timestamp, as=LastSeen),
    sum(PrecursorHit, as=Precursors),
    sum(ServiceHit, as=ServicesCreated),
    sum(ProcessHit, as=ServiceProcesses),
    collect([Step, ServiceImagePath, FileName, CommandLine], separator=" → ", as=Timeline)
  ], limit=max)
| DurationMs:=LastSeen-FirstSeen
| Precursors>0 ServicesCreated>0 ServiceProcesses>0 DurationMs<=300000
| sort(FirstSeen, order=desc)

Analyst reasoning

Likely false positives: temporary services created by SCCM, endpoint-management, backup, and remote-support tooling. Falcon event names and normalization differ by sensor and parser version, so validate the field map using one known benign remote deployment before production use. Preserve any mismatch for review.

Week 17 · Day 5

Simple Python correlator

Page 6 / 8

What should be done

Save Day 1 as events.jsonl. Group rows by scenario, sort by time, find a service creation, look backward for the remote precursor, then look forward for the matching services.exe child.

Easy reading plan

  1. Read one JSON object per line.
  2. Group by scenario_id.
  3. Skip local creates and exact approved tuples.
  4. Check the five-minute precursor window.
  5. Check the two-minute process window.

Python answer

import json
from collections import defaultdict
from datetime import datetime

WINDOW = 300          # share/control → service create
START_WINDOW = 120    # service create → services.exe child
APPROVED = {
    ("sccm-mp01", "corp\\svc_sccm", "ccmexecupgrade", "c:/windows/ccmsetup/ccmsetup.exe"),
    ("rmm-01", "corp\\svc_endpoint_mgmt", "contosoendpointagentupgrade", "c:/program files/contoso endpoint/agent-upgrade.exe"),
    ("backup-01", "corp\\svc_backup", "corpbackupsnapshotsvc", "c:/program files/corpbackup/snapshot-agent.exe"),
    ("support-gw01", "corp\\svc_remote_support", "approvedremotesupportsvc", "c:/program files/approved support/support-host.exe"),
}

def stamp(text):
    return datetime.fromisoformat(text.replace("Z", "+00:00"))

def clean(text):
    return text.replace("\\", "/").lower()

def is_approved(service):
    key = (service["source"].lower(), service["account"].lower(),
           service["service_name"].lower(), clean(service["service_path"]))
    return key in APPROVED

def matches(rows):
    rows.sort(key=lambda e: e["timestamp"])
    for service in rows:
        if service["event_type"] != "service" or service["action"] != "create":
            continue
        if service["source"] == service["target"] or is_approved(service):
            continue
        made = stamp(service["timestamp"])
        before = [e for e in rows if e["source"] == service["source"]
                  and e["target"] == service["target"]
                  and e["account"] == service["account"]
                  and e["event_type"] in {"share", "service_control"}
                  and 0 <= (made - stamp(e["timestamp"])).total_seconds() <= WINDOW
                  and (e["event_type"] != "share" or e["share"].upper() in {"ADMIN$", "C$"})]
        after = [e for e in rows if e["event_type"] == "process"
                 and e["target"] == service["target"]
                 and e["service_name"].lower() == service["service_name"].lower()
                 and clean(e["parent"]).endswith("/services.exe")
                 and 0 <= (stamp(e["timestamp"]) - made).total_seconds() <= START_WINDOW]
        if before and after:
            return service
    return None

groups = defaultdict(list)
with open("events.jsonl", encoding="utf-8") as handle:
    for line in handle:
        event = json.loads(line)
        groups[event["scenario_id"]].append(event)

for scenario, rows in sorted(groups.items()):
    service = matches(rows)
    if service:
        print(f"MATCH {scenario}: {service['source']} → {service['target']} | {service['service_name']}")

Week 17 · Day 6

Go compact timeline per target

Page 7 / 8

What should be done

Use the same events.jsonl. Group events by target host, sort each target chronologically, and print one compact line per event. This makes remote source, service creation, execution, and cleanup easy to review.

Why a timeline helps

A single service event can be noisy. A short ordered view shows whether share or service-control activity came first, whether services.exe launched the service, and whether cleanup followed.

The program deliberately builds a timeline; it does not hide approved rows.

Go answer

package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "sort"
    "time"
)

type Event struct {
    Time        string `json:"timestamp"`
    Type        string `json:"event_type"`
    Action      string `json:"action"`
    Source      string `json:"source"`
    Target      string `json:"target"`
    Share       string `json:"share"`
    ServiceName string `json:"service_name"`
    ProcessName string `json:"process_name"`
}

func main() {
    file, err := os.Open("events.jsonl")
    if err != nil { panic(err) }
    defer file.Close()

    byTarget := map[string][]Event{}
    scan := bufio.NewScanner(file)
    for scan.Scan() {
        var event Event
        if json.Unmarshal(scan.Bytes(), &event) == nil {
            byTarget[event.Target] = append(byTarget[event.Target], event)
        }
    }
    if err := scan.Err(); err != nil { panic(err) }

    targets := make([]string, 0, len(byTarget))
    for target := range byTarget { targets = append(targets, target) }
    sort.Strings(targets)

    for _, target := range targets {
        rows := byTarget[target]
        sort.Slice(rows, func(i, j int) bool { return rows[i].Time < rows[j].Time })
        fmt.Printf("\n%s\n", target)
        for _, event := range rows {
            when, _ := time.Parse(time.RFC3339, event.Time)
            detail := event.Action
            if event.Share != "" { detail += " " + event.Share }
            if event.ServiceName != "" { detail += " " + event.ServiceName }
            if event.ProcessName != "" { detail += " " + event.ProcessName }
            fmt.Printf("  %s  %-15s  %s → %s  %s\n",
                when.Format("15:04:05"), event.Type, event.Source, event.Target, detail)
        }
    }
}

Verify backup server, snapshot job, helper service, target, and schedule.

Remote support

Verify support gateway, approved session, ticket, operator, user contact, and service path.

Near miss
