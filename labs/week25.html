Week 25 Â· Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Start with the normalized KubernetesAudit table.
  2. Keep create pods/exec events.
  3. Read the first item in the command array.
  4. Keep sh or bash.
  5. Exclude only an approved workflow that also has a change reference.

Why the tuning is narrow

Do not allowlist a whole namespace, SRE team, or service account. This example requires two pieces of context together: an explicit approval marker and a non-empty change or incident reference.

In production, create approval context from a controlled source and expire it after the change window.

KQL answer

Validation place: adapt the table and field names to the Kubernetes audit data in your Microsoft Sentinel or Azure Data Explorer workspace.

let Shells = dynamic(["sh", "bash"]);
KubernetesAudit
| where Verb =~ "create"
| where Resource =~ "pods" and Subresource =~ "exec"
| extend Commands = todynamic(Command)
| extend FirstCommand = tolower(tostring(Commands[0]))
| extend ShellName = tostring(split(FirstCommand, "/")[-1])
| where ShellName in (Shells)
| where not(ApprovedWorkflow == true and NamespaceApproved == true
            and WithinChangeWindow == true and isnotempty(ChangeId))
| project Timestamp, User, SourceIp, Namespace, Pod,
          Command = tostring(Commands), ChangeId
| order by Timestamp desc

Analyst reasoning

Likely false positives: SRE debugging, urgent break-fix work, and approved deployment automation. Confirm the change or incident owner, time window, source network, target namespace and pod, exact command, and whether the activity matches the documented workflow. A shell alone is not proof of compromise.

Week 25 Â· Day 5

Simple Python audit parser

Page 6 / 8

What should be done

Save the Day 1 fixtures as events.jsonl. The program reads one line at a time, handles broken JSON without stopping, checks that command is a list, extracts the first command safely, and prints risky event numbers.

Easy reading plan

  1. Open the JSONL file.
  2. Try to parse each line.
  3. Get the first command safely.
  4. Check exec + shell behavior.
  5. Skip a fully documented approved workflow.

Python answer

import json

SHELLS = {"sh", "bash"}


def first_command(event):
    command = event.get("command", [])
    if not isinstance(command, list) or not command:
        return ""
    return str(command[0]).rsplit("/", 1)[-1].lower()


def is_risky(event):
    is_exec = (
        event.get("verb", "").lower() == "create"
        and event.get("resource", "").lower() == "pods"
        and event.get("subresource", "").lower() == "exec"
    )
    approved = (
        event.get("approved_workflow") is True
        and event.get("namespace_approved") is True
        and event.get("within_change_window") is True
        and bool(event.get("change_id"))
    )
    return is_exec and first_command(event) in SHELLS and not approved


with open("events.jsonl", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        try:
            event = json.loads(line)
        except json.JSONDecodeError:
            print(f"Skipped invalid JSON on line {line_number}")
            continue

        if is_risky(event):
            print(event.get("event_number", line_number), first_command(event))

Go answer

package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
)

type Event struct {
    Verb        string `json:"verb"`
    Resource    string `json:"resource"`
    Subresource string `json:"subresource"`
    Namespace   string `json:"namespace"`
    User        string `json:"user"`
    Pod         string `json:"pod"`
}

func main() {
    file, err := os.Open("events.jsonl")
    if err != nil {
        fmt.Println("open error:", err)
        return
    }
    defer file.Close()

    counts := map[string]int{}
    scanner := bufio.NewScanner(file)

    for scanner.Scan() {
        var event Event
        if json.Unmarshal(scanner.Bytes(), &event) != nil {
            continue
        }
        if event.Verb == "create" && event.Resource == "pods" && event.Subresource == "exec" {
            key := event.Namespace + " | " + event.User + " | " + event.Pod
            counts[key]++
        }
    }

    for key, count := range counts {
        fmt.Printf("%s = %d\n", key, count)
    }
}

Analyst reasoning

Likely false positives: SRE and deployment identities may naturally have the highest exec counts. Volume is context, not guilt. Compare the summary with role ownership, namespace sensitivity, source IP, change windows, and the exact commands before tuning.
