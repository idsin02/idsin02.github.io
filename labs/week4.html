Your seven-day path

Week goal

Find a newly created executable launched from Downloads, Temp, or a directory tied to an archive. Keep path, hash, signer, prevalence, and archive parent in the analyst output.

Success: events 1–4 alert; events 5–8 stay quiet for a clear reason.

Simple decision

  1. Join file creation to process start by device + SHA-256.
  2. Require execution within five minutes.
  3. Require a target location or archive lineage.
  4. Suppress only with strong, current installer evidence.

Week 4 · Day 2

KQL behavior query + tuning

Page 3 / 8

What to do

  1. Prepare file-create rows.
  2. Join process starts on device + SHA-256.
  3. Keep starts within five minutes.
  4. Keep Downloads, Temp, or archive-linked paths.
  5. Suppress only signed, common files with current evidence.

Lab schema

The query uses two easy normalized tables: EndpointFileCreate and EndpointProcessStart. Map your product fields before production use.

A valid signature alone is not an allowlist. Require exact evidence with an owner and expiry.

KQL answer

Live-tenant execution was not available. The fixture semantics were validated locally; field names still require mapping.

let FreshWindow = 5m;
let ApprovedInstallers = datatable(SHA256:string, Evidence:string, Expires:datetime)
[
  "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "CAB-2026-041; owner=Workplace IT", datetime(2026-12-31),
  "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb", "CHG-2026-908; owner=Endpoint Platform", datetime(2026-11-30)
];
let Creates = EndpointFileCreate
| project DeviceId, SHA256, CreateTime=Timestamp, CreatedPath=FilePath,
          SignerStatus, GlobalPrevalence, ArchiveParent;
EndpointProcessStart
| project DeviceId, SHA256, StartTime=Timestamp, ProcessPath, ParentProcess, User
| join kind=innerunique Creates on DeviceId, SHA256
| where StartTime between (CreateTime .. CreateTime + FreshWindow)
| extend PathLower=tolower(ProcessPath)
| where PathLower contains @"\downloads\"
    or PathLower contains @"\temp\"
    or isnotempty(ArchiveParent)
| lookup kind=leftouter ApprovedInstallers on SHA256
| extend EvidenceIsCurrent=isnotempty(Evidence) and Expires > now()
| where not(SignerStatus == "Valid"
            and GlobalPrevalence >= 1000
            and EvidenceIsCurrent)
| project StartTime, DeviceId, User, ProcessPath, SHA256,
          SignerStatus, GlobalPrevalence, ArchiveParent, ParentProcess
| order by StartTime desc

Analyst reasoning

Likely false positives: portable apps, interactive installers, developer build output copied into a user-writable path, and vendor updaters. Keep them visible until signer validity, hash or package identity, prevalence, owner, scope, and expiry are verified. Prefer a narrow hash-based exclusion over a broad path or publisher exclusion.

CrowdStrike CQL answer

Not run in a Falcon tenant. Confirm event names and enrichment fields in one known event before use.

(#event_simpleName=FileWritten OR #event_simpleName=ProcessRollup2)
| case {
    #event_simpleName=FileWritten
      | event_kind := "create"
      | event_time := @timestamp
      | path := TargetFileName;
    #event_simpleName=ProcessRollup2
      | event_kind := "start"
      | event_time := @timestamp
      | path := ImageFileName;
  }
| groupBy([aid, SHA256HashData], function=[
    collect([event_kind, event_time, path, ParentBaseFileName,
             SignerStatus, GlobalPrevalence, ArchiveParent,
             AllowlistEvidence], limit=20),
    min(event_time, as=first_seen),
    max(event_time, as=last_seen)
  ], limit=max)
| test(first_seen < last_seen and last_seen - first_seen <= 300000)
| test(path=/\\Downloads\\|\\Temp\\/i or ArchiveParent!="")
| evidence_current := AllowlistEvidence=/owner=.*expires=/i
| test(not(SignerStatus="Valid" and GlobalPrevalence>=1000 and evidence_current=true))
| table([last_seen, aid, path, SHA256HashData, SignerStatus,
         GlobalPrevalence, ArchiveParent, ParentBaseFileName])

Analyst reasoning

Likely false positives: portable utilities, approved installers, developer artifacts, and updater services. Confirm that GlobalPrevalence, ArchiveParent, and AllowlistEvidence exist in your Falcon data or add them through enrichment. Do not silently treat a missing field as approval.

Week 4 · Day 5

Mark fresh files with Python

Page 6 / 8

What the code does

  1. Read one JSON object per line.
  2. Parse the creation and start timestamps.
  3. Subtract created from started.
  4. Mark 0–300 seconds as FRESH.
Run: python week4_fresh.py

Expected result

Events 1–5, 7, and 8 are temporally fresh. Event 6 is stale. Location and suppression are separate decisions used by the final detector.

Build validation: Executed · 8 fixture lines

Python answer

import json
from datetime import datetime

WINDOW_SECONDS = 300

def time_value(text):
    return datetime.fromisoformat(text.replace("Z", "+00:00"))

def is_fresh(event):
    created = time_value(event["file_create_time"])
    started = time_value(event["process_start_time"])
    seconds = (started - created).total_seconds()
    return 0 <= seconds <= WINDOW_SECONDS, int(seconds)

with open("events.jsonl", encoding="utf-8") as source:
    for line in source:
        event = json.loads(line)
        fresh, seconds = is_fresh(event)
        mark = "FRESH" if fresh else "STALE"
        print(f"Event {event['event_number']}: {mark} ({seconds}s) -> {event['process_path']}")

Analyst reasoning

Likely false positives: a browser finishing an installer download before the user opens it, a self-extracting archive starting its setup file, a developer immediately testing a build, or a vendor updater staging in Temp. Freshness raises priority; it is not proof of maliciousness.

Week 4 · Day 6

Group paths with Go

Page 7 / 8

What the code does

  1. Read the same JSONL file.
  2. Classify each path as Downloads, Temp, extracted archive, or other.
  3. Read the extension.
  4. Count each directory + extension pair.
Run: go run week4_group.go

Why group first?

Counts show where executions cluster. A sudden rise in Temp .exe launches can guide tuning or hunting even before you add more complex logic.

Build validation: Not run — Go tool unavailable

Go answer

package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "path/filepath"
    "sort"
    "strings"
)

type Event struct {
    ProcessPath   string `json:"process_path"`
    ArchiveParent string `json:"archive_parent"`
}

func directory(e Event) string {
    path := strings.ToLower(e.ProcessPath)
    if strings.Contains(path, `\downloads\`) { return "Downloads" }
    if strings.Contains(path, `\temp\`) { return "Temp" }
    if e.ArchiveParent != "" { return "Extracted archive" }
    return "Other"
}

func main() {
    file, err := os.Open("events.jsonl")
    if err != nil { panic(err) }
    defer file.Close()

    counts := map[string]int{}
    scanner := bufio.NewScanner(file)
    for scanner.Scan() {
        var e Event
        if json.Unmarshal(scanner.Bytes(), &e) != nil { continue }
        ext := strings.ToLower(filepath.Ext(e.ProcessPath))
        counts[directory(e)+" / "+ext]++
    }
    if err := scanner.Err(); err != nil { panic(err) }

    keys := make([]string, 0, len(counts))
    for key := range counts { keys = append(keys, key) }
    sort.Strings(keys)
    for _, key := range keys { fmt.Printf("%-25s %d\n", key, counts[key]) }
}

Analyst reasoning

Likely false positives: portable app collections in Downloads, setup bundles unpacking to Temp, developer package tests, and fleet-wide vendor updaters. Use the grouping as a baseline, then investigate rare extensions, rare hashes, low prevalence, and unusual parent processes.

Final analyst reasoning

Likely false positives: portable apps, installers, developer build output, and vendor updaters. A safe suppression should be narrow, attributable, and reversible: exact hash or package identity, valid expected signer, sufficient prevalence for your environment, documented owner, approved scope, and an expiry. If the archive parent, hash, signer, or command lineage differs, keep the alert visible.

Portfolio evidence: keep the fixtures, validation output, rule versions, field map, and tuning record together. That proves the detection works and shows why each exception exists.
