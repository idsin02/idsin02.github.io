Week goal

Important boundary

A first-seen domain is not automatically malicious. The lab creates a triage lead, not a verdict. An analyst still checks the command line, parent process, user activity, domain age, DNS answers, and nearby connections.

Do not turn “rare” into “malicious.”

Week 14 · Day 2

KQL behavior query + tuning

Page 3 / 8

Build it in five steps

  1. Use the last 14 days, excluding today, as the baseline.
  2. Count each normalized domain.
  3. Read today’s DNS events from script hosts.
  4. Left-join the baseline and turn missing counts into zero.
  5. Remove only exact approved domains.

Narrow tuning

The allowlist contains complete normalized domains, not suffixes. Exact equality filters telemetry.corp.example but keeps telemetry.corp.example.evil.net visible.

Confirm the real action type and field names with one known DNS event before deployment.

KQL answer

let BaselineStart = ago(14d);
let HuntStart = startofday(now());
let ScriptHosts = dynamic(["powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "python.exe", "python3.exe"]);
let ApprovedDomains = dynamic(["telemetry.corp.example", "approved-scanner.security.example"]);
let Baseline =
    DeviceNetworkEvents
    | where Timestamp between (BaselineStart .. HuntStart)
    | where ActionType == "DnsQueryResponse"
    | extend domain = tolower(trim_end(@"[.]$", RemoteUrl))
    | summarize baseline_count = count() by domain;
DeviceNetworkEvents
| where Timestamp > HuntStart
| where ActionType == "DnsQueryResponse"
| extend domain = tolower(trim_end(@"[.]$", RemoteUrl)),
         process = tolower(InitiatingProcessFileName)
| where process in~ (ScriptHosts)
| join kind=leftouter Baseline on domain
| extend baseline_count = coalesce(baseline_count, 0)
| where baseline_count == 0
| where domain !in~ (ApprovedDomains)
| project Timestamp, DeviceName, InitiatingProcessAccountName,
          process, InitiatingProcessParentFileName, domain, baseline_count
| order by Timestamp desc

Analyst reasoning

Likely false positives: a new SaaS service contacted for the first time, unique CDN subdomains, developer tools fetching packages or documentation, and approved security testing. Before tuning, verify the exact domain, process command line, parent process, owner, expected devices, and expiry date. Keep an allowlist record with a ticket or change reference.

Week 14 · Day 5

Build a domain table with Python

Page 6 / 8

What should be done

Read events.jsonl, normalize each domain, count how often it appears in this small file, and remember which domains have a baseline count of zero. Print one easy frequency table.

Easy reading plan

  1. Create an empty counter.
  2. Read one JSON line.
  3. Normalize and count the domain.
  4. Put baseline-zero domains in a set.
  5. Print the sorted table.

Python answer

import json
from collections import Counter

counts = Counter()
first_seen = set()

with open("events.jsonl", encoding="utf-8") as file:
    for line in file:
        event = json.loads(line)
        domain = event["domain"].lower().removesuffix(".")

        counts[domain] += 1
        if event["baseline_count"] == 0:
            first_seen.add(domain)

print(f"{'domain':45} count  first_seen")
for domain in sorted(counts):
    flag = "YES" if domain in first_seen else "no"
    print(f"{domain:45} {counts[domain]:5}  {flag}")

The table separates “how often it appears in this file” from “whether it appeared in the earlier baseline.” Likely false positives: new SaaS services, one-off CDN subdomains, developer package requests, and approved security testing. Frequency helps prioritize; it does not determine intent.

Week 14 · Day 6

Stream DNS JSONL with Go

Page 7 / 8

What should be done

Use a scanner to read one event at a time. Normalize the domain, increase its count in a map, and print the running total. This version stays intentionally small.

Run and first lines

go run main.go
sync-checker.pages.dev -> 1
api-reporting-storage.com -> 1
login.microsoftonline.com -> 1
sync-checker.pages.dev -> 2

Go answer

package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "strings"
)

type Event struct {
    Domain string `json:"domain"`
}

func main() {
    file, err := os.Open("events.jsonl")
    if err != nil {
        fmt.Println("open error:", err)
        return
    }
    defer file.Close()

    counts := map[string]int{}
    scanner := bufio.NewScanner(file)

    for scanner.Scan() {
        var event Event
        if json.Unmarshal(scanner.Bytes(), &event) != nil {
            continue
        }

        domain := strings.TrimSuffix(strings.ToLower(event.Domain), ".")
        counts[domain]++
        fmt.Printf("%s -> %d\n", domain, counts[domain])
    }

    if err := scanner.Err(); err != nil {
        fmt.Println("read error:", err)
    }
}

Analyst reasoning

The map is a simple in-memory counter, not a production baseline store. Likely false positives: new SaaS services, CDN subdomains, developer tools, and security testing. A production version would add time windows, bounded storage, tests, metrics, and a reviewed exact-domain allowlist.
