How this learning plan works

The six-month roadmap is a sequence of small, publishable detection-engineering exercises. Each week starts with telemetry and ends with a validated hunt. Week 1 deliberately uses one clear behavior: Word, Excel, or PowerPoint starts PowerShell. The attached roadmap emphasizes reproducible telemetry, malicious and benign test data, false-positive tuning, and detection-as-code evidence; this lab applies that idea without making the code complex.

Week goal

Detect WINWORD.EXE, EXCEL.EXE, or POWERPNT.EXE creating powershell.exe or pwsh.exe, while excluding one explicitly approved automation path.

Success means events 1 and 2 match; events 3, 4, and 5 do not.

Week 1 · Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Start with DeviceProcessEvents.
  2. Keep only the three Office parents.
  3. Keep only PowerShell children.
  4. Exclude the exact approved user + script pair.
  5. Project the fields an analyst needs.

Why the tuning is narrow

Do not allowlist every macro, add-in, user, or PowerShell command. The example exclusion requires both the approved service account and the approved script path. Any change to either value remains visible.

Validate allowlists with an owner and expiry date before using them in production.

KQL answer

Validation place: paste this into Microsoft Defender Advanced Hunting after confirming that DeviceProcessEvents is available.

let ApprovedUsers = dynamic(["svc_office_automation"]);
DeviceProcessEvents
| where InitiatingProcessFileName in~ ("WINWORD.EXE", "EXCEL.EXE", "POWERPNT.EXE")
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where not(
    AccountName in~ (ApprovedUsers)
    and ProcessCommandLine has @"C:\ProgramData\Contoso\OfficeAutomation\inventory.ps1"
)
| project Timestamp, DeviceName, AccountName,
          InitiatingProcessFileName, FileName, ProcessCommandLine
| order by Timestamp desc

Analyst note

Likely false positives: signed Office add-ins that call approved PowerShell, approved macros used for reporting or document workflows, and IT automation launched from Office. Tune only after confirming the signer, script path, user or service account, command line, owner, and expected devices.

| ParentBaseFileName=/^(WINWORD|EXCEL|POWERPNT)\.EXE$/i
| FileName=/^(powershell|pwsh)\.exe$/i

    UserName="svc_office_automation"

  )
| table([@timestamp, ComputerName, UserName,
         ParentBaseFileName, FileName, CommandLine])

Analyst note

Likely false positives: approved macros, signed add-ins, and IT support workflows. Falcon tenants can use different field availability or normalization, so confirm the field map with one known process event before relying on the query.

Sigma answer

title: Office Application Spawns PowerShell
logsource:
  product: windows
  category: process_creation
detection:
  selection_parent:
    ParentImage|endswith:
      - '\WINWORD.EXE'
      - '\EXCEL.EXE'
      - '\POWERPNT.EXE'
  selection_child:
    Image|endswith:
      - '\powershell.exe'
      - '\pwsh.exe'
  filter_approved_automation:
    User|endswith: '\svc_office_automation'
    CommandLine|contains: '\ProgramData\Contoso\OfficeAutomation\inventory.ps1'
  condition: selection_parent and selection_child and not filter_approved_automation
falsepositives:
  - Signed Office add-ins launching approved PowerShell
  - Approved macros that call PowerShell
  - IT automation launched from Office
level: medium

Analyst note

A Sigma match means the process relationship deserves review. It does not prove the document is malicious. Compare the command line, file origin, signer, user behavior, device role, and nearby process or network activity.

Week 1 · Day 5

Simple Python filter

Page 6 / 8

What should be done

Save the Day 1 data as events.jsonl. The program reads one line at a time and prints the matching event numbers. For the supplied fixtures, the answer is 1 and 2.

Easy reading plan

  1. Open the file.
  2. Turn each line into a dictionary.
  3. Get the final executable name.
  4. Check Office + PowerShell.
  5. Skip the approved user + script pair.

Python answer

import json

OFFICE = {"winword.exe", "excel.exe", "powerpnt.exe"}
POWERSHELL = {"powershell.exe", "pwsh.exe"}


def name(path):
    return path.replace("\\", "/").split("/")[-1].lower()


with open("events.jsonl", encoding="utf-8") as file:
    for line in file:
        event = json.loads(line)

        approved = (
            event["user"].lower() == "corp\\svc_office_automation"
            and "\\programdata\\contoso\\officeautomation\\inventory.ps1"
            in event["command_line"].lower()
        )

        if (
            name(event["parent_image"]) in OFFICE
            and name(event["child_image"]) in POWERSHELL
            and not approved
        ):
            print(event["event_number"])

Week 1 · Day 6

Simple Go line reader

Page 7 / 8

What should be done

Read the same JSONL file with a scanner. For every non-approved match, print the parent and child executable names. Two lines should be printed.

Run and expected output

go run main.go
WINWORD.EXE -> powershell.exe
EXCEL.EXE -> pwsh.exe

Go answer

package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "strings"
)

type Event struct {
    ParentImage string `json:"parent_image"`
    ChildImage  string `json:"child_image"`
    CommandLine string `json:"command_line"`
    User        string `json:"user"`
}

func name(path string) string {
    parts := strings.Split(strings.ReplaceAll(path, "\\", "/"), "/")
    return parts[len(parts)-1]
}

func main() {
    file, _ := os.Open("events.jsonl")
    defer file.Close()

    office := map[string]bool{"winword.exe": true, "excel.exe": true, "powerpnt.exe": true}
    shells := map[string]bool{"powershell.exe": true, "pwsh.exe": true}
    scanner := bufio.NewScanner(file)

    for scanner.Scan() {
        var event Event
        json.Unmarshal(scanner.Bytes(), &event)

        parent := strings.ToLower(name(event.ParentImage))
        child := strings.ToLower(name(event.ChildImage))
        approved := strings.EqualFold(event.User, `CORP\svc_office_automation`) &&
            strings.Contains(strings.ToLower(event.CommandLine), `\programdata\contoso\officeautomation\inventory.ps1`)

        if office[parent] && shells[child] && !approved {
            fmt.Println(name(event.ParentImage), "->", name(event.ChildImage))
        }
    }
}

Analyst note

This version stays intentionally small for Day 6. A later engineering lab can add file-open errors, JSON errors, scanner errors, tests, and CLI flags. Here, the learning goal is simply streaming one event per line and applying the same behavior.

Analyst notes: false positives

Signed add-ins

Verify signer, add-in path, publisher, affected Office app, and whether PowerShell is expected.

Approved macros

Verify macro owner, document source, command line, script path, and business purpose.

IT automation

Verify service account, managed device list, approved script hash or path, owner, and expiry date.
