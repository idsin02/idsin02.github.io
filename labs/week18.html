Executable launched from removable media

Find a Linux process whose executable image or parent comes from a newly mounted removable drive. Correlate the mount, matching file, and later process instead of relying on a campaign-specific filename.

Week goal

Connect three facts on the same device: a removable volume is mounted, a file is observed below that mount point, and a later process starts with either its image or its parent below the same mount point.

Success means S1 and S2 match. S3–S10 must stay quiet.

Generic behavior, not attribution

The capstone does not search for TEMP.Hex, a particular USB label, or one malware family. Paths, timing, volume context, hashes, and signers are evidence; none alone proves malicious intent.

Week 18 · Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Normalize mount, file, and process paths.
  2. Join by device and time.
  3. Require the file to equal the process image or parent.
  4. Require that origin to sit below the exact mount point.
  5. Remove only exact approved profiles.

Tuning choice

The example uses a normalized table named LinuxRemovableEvents_CL. A broad rule such as “ignore signed files” is unsafe. The signer, SHA-256, volume, and origin path must all match the approved record.

Mount roots are data, not a hard-coded list of /media folders.

KQL answer

let Window = 20m;
let Approved = datatable(VolumeId:string, OriginPath:string, SHA256:string, Signer:string)
[
  "VOL-ENG-01", "/media/field/ENGKIT/bin/hwcheck", "3333333333333333333333333333333333333333333333333333333333333333", "Acme Field Engineering",
  "VOL-OS-01", "/media/installer/OS_DEPLOY/setup.run", "4444444444444444444444444444444444444444444444444444444444444444", "Contoso IT",
  "VOL-IR-01", "/media/forensics/IR_KIT/bin/imager", "5555555555555555555555555555555555555555555555555555555555555555", "Evidence Labs",
  "VOL-VD-01", "/media/support/VENDOR_DIAG/diag.sh", "6666666666666666666666666666666666666666666666666666666666666666", "Vendor Diagnostics Ltd"
];
let Mounts = LinuxRemovableEvents_CL
| where EventType == "mount" and Action == "mount" and IsRemovable == true
| extend MountPoint = trim_end(@"/+", replace_string(MountPoint, @"\", "/"))
| project Device, VolumeId, VolumeLabel, Bus, MountPoint, MountTime=TimeGenerated;
let Files = LinuxRemovableEvents_CL
| where EventType == "file" and Action in ("create", "observe")
| extend FilePath = replace_string(FilePath, @"\", "/")
| project Device, FilePath, SHA256, Signer, FileTime=TimeGenerated;
let Processes = LinuxRemovableEvents_CL
| where EventType == "process" and Action == "start"
| extend ImagePath = replace_string(ExecutablePath, @"\", "/"),
         ParentPath = replace_string(ParentPath, @"\", "/")
| project Device, User, ImagePath, ParentPath, CommandLine, ProcessTime=TimeGenerated;
Mounts
| join kind=inner Processes on Device
| where ProcessTime between (MountTime .. MountTime + Window)
| extend OriginPath = case(
    ImagePath == MountPoint or ImagePath startswith strcat(MountPoint, "/"), ImagePath,
    ParentPath == MountPoint or ParentPath startswith strcat(MountPoint, "/"), ParentPath,
    "")
| where isnotempty(OriginPath)
| join kind=inner Files on Device
| where FileTime between (MountTime .. ProcessTime) and FilePath == OriginPath
| join kind=leftanti Approved on VolumeId, OriginPath, SHA256, Signer
| project ProcessTime, Device, User, VolumeId, VolumeLabel, Bus, MountPoint,
          OriginPath, ImagePath, ParentPath, SHA256, Signer, CommandLine
| order by ProcessTime desc

Analyst reasoning

Likely false positives: approved field tools, software installers, forensic media, and vendor diagnostics. Confirm the volume owner, business purpose, exact path, SHA-256, signer or package provenance, user, and ticket window. A signer alone is not enough, and unsigned does not automatically mean malicious.

CrowdStrike CQL answer

#event_simpleName=/^(LinuxMount|FileWritten|ProcessRollup2)$/
| case {
    #event_simpleName=LinuxMount IsRemovable=true
      | Stage:="mount" | MountHit:=1 | FileHit:=0 | ProcessHit:=0
      | MountPointNorm:=lower(MountPoint);
    #event_simpleName=FileWritten
      | Stage:="file" | MountHit:=0 | FileHit:=1 | ProcessHit:=0
      | OriginPath:=lower(TargetFileName);
    #event_simpleName=ProcessRollup2
      | Stage:="process" | MountHit:=0 | FileHit:=0 | ProcessHit:=1
      | ImagePathNorm:=lower(FilePath) | ParentPathNorm:=lower(ParentImageFilePath);
    * | Stage:="other" | MountHit:=0 | FileHit:=0 | ProcessHit:=0;
  }
| not (
    (VolumeSerialNumber="VOL-ENG-01" OriginPath="/media/field/engkit/bin/hwcheck" SHA256HashData="3333333333333333333333333333333333333333333333333333333333333333" SignerName="Acme Field Engineering") or
    (VolumeSerialNumber="VOL-OS-01" OriginPath="/media/installer/os_deploy/setup.run" SHA256HashData="4444444444444444444444444444444444444444444444444444444444444444" SignerName="Contoso IT") or
    (VolumeSerialNumber="VOL-IR-01" OriginPath="/media/forensics/ir_kit/bin/imager" SHA256HashData="5555555555555555555555555555555555555555555555555555555555555555" SignerName="Evidence Labs") or
    (VolumeSerialNumber="VOL-VD-01" OriginPath="/media/support/vendor_diag/diag.sh" SHA256HashData="6666666666666666666666666666666666666666666666666666666666666666" SignerName="Vendor Diagnostics Ltd")
  )
| groupBy([aid, VolumeSerialNumber], function=[
    min(@timestamp, as=FirstSeen),
    max(@timestamp, as=LastSeen),
    sum(MountHit, as=Mounts),
    sum(FileHit, as=Files),
    sum(ProcessHit, as=Processes),
    collect([Stage, MountPointNorm, OriginPath, ImagePathNorm, ParentPathNorm, SHA256HashData, SignerName], separator=" → ", as=Evidence)
  ], limit=max)
| DurationMs:=LastSeen-FirstSeen
| Mounts>0 Files>0 Processes>0 DurationMs<=1200000
| sort(LastSeen, order=desc)

Analyst reasoning

Likely false positives: field utilities, removable installation media, forensic response kits, and vendor support bundles. Validate the local event schema first: some Falcon deployments need a custom mount data source or enrichment. Review collected evidence to confirm that image or parent is actually below the observed mount point before escalating.

Week 18 · Day 5

Simple Python mount mapper

Page 6 / 8

What should be done

Save Day 1 as events.jsonl. For each removable mount, look forward 20 minutes. If a later process image or parent is below the mount, require a matching file event and then check the exact allowlist.

Easy reading plan

  1. Read and sort JSON lines.
  2. Visit each removable mount.
  3. Compare image and parent paths safely.
  4. Confirm the file event.
  5. Skip exact approved tuples and print matches.

Python answer

import json
import posixpath
from datetime import datetime

WINDOW_SECONDS = 20 * 60
APPROVED = {
    ("VOL-ENG-01", "/media/field/ENGKIT/bin/hwcheck", "3" * 64, "Acme Field Engineering"),
    ("VOL-OS-01", "/media/installer/OS_DEPLOY/setup.run", "4" * 64, "Contoso IT"),
    ("VOL-IR-01", "/media/forensics/IR_KIT/bin/imager", "5" * 64, "Evidence Labs"),
    ("VOL-VD-01", "/media/support/VENDOR_DIAG/diag.sh", "6" * 64, "Vendor Diagnostics Ltd"),
}

def time_value(text):
    return datetime.fromisoformat(text.replace("Z", "+00:00"))

def clean(value):
    value = (value or "").replace("\\", "/")
    return posixpath.normpath(value) if value else ""

def below(path, mount):
    path, mount = clean(path), clean(mount)
    return path == mount or path.startswith(mount.rstrip("/") + "/")

with open("events.jsonl", encoding="utf-8") as handle:
    events = [json.loads(line) for line in handle if line.strip()]

events.sort(key=lambda event: event["timestamp"])
mounts = [event for event in events
          if event["event_type"] == "mount" and event.get("removable") is True]

for mount in mounts:
    start = time_value(mount["timestamp"])
    for process in events:
        if process["event_type"] != "process" or process["device"] != mount["device"]:
            continue
        age = (time_value(process["timestamp"]) - start).total_seconds()
        if not 0 <= age <= WINDOW_SECONDS:
            continue

        image = process.get("executable_path", "")
        parent = process.get("parent_path", "")
        origin = image if below(image, mount["mount_point"]) else parent if below(parent, mount["mount_point"]) else ""
        if not origin:
            continue

        file_event = next((event for event in events
            if event["event_type"] == "file"
            and event["device"] == mount["device"]
            and clean(event.get("file_path")) == clean(origin)
            and start <= time_value(event["timestamp"]) <= time_value(process["timestamp"])), None)
        if not file_event:
            continue

        profile = (mount["volume_id"], clean(origin),
                   file_event["sha256"], file_event["signer"])
        if profile in APPROVED:
            continue

        print(f"MATCH {process['scenario_id']}: {mount['mount_point']} → {clean(origin)} → {process['executable_path']}")

Week 18 · Day 6

Go drive and mount path normalization

Page 7 / 8

What should be done

Normalize separators, file://, repeated slashes, Windows drive-letter case, and trailing mount separators. Then represent paths below a known mount as <removable>/relative/path.

Why this matters

The same removable path may appear as /run/media/user/USB//file, file:///Volumes/USB/file, or E:\USB\file. Normalize before comparing, but retain the original value for evidence.

Normalization makes equivalent paths comparable; it does not decide whether a volume is removable.

Go answer

package main

import (
    "fmt"
    "path"
    "strings"
)

type Record struct {
    Mount string
    Path  string
}

func clean(value string) string {
    value = strings.Trim(strings.TrimSpace(value), "\"")
    value = strings.TrimPrefix(value, "file://")
    value = strings.ReplaceAll(value, "\\", "/")
    value = path.Clean(value)
    if len(value) >= 2 && value[1] == ':' {
        value = strings.ToLower(value[:1]) + value[1:]
    }
    return value
}

func removableName(mount, file string) string {
    mount = strings.TrimSuffix(clean(mount), "/")
    file = clean(file)
    prefix := mount + "/"
    if file == mount {
        return "<removable>"
    }
    if strings.HasPrefix(strings.ToLower(file), strings.ToLower(prefix)) {
        return "<removable>/" + file[len(prefix):]
    }
    return file
}

func main() {
    samples := []Record{
        {"/media/alex/USB_BLUE/", "/media/alex/USB_BLUE/tools/audit-helper"},
        {"/run/media/maya/VENDOR_USB", "/run/media/maya/VENDOR_USB//collect.sh"},
        {"E:\\", "E:\\Toolkit\\diag.exe"},
        {"/Volumes/IR_KIT", "file:///Volumes/IR_KIT/bin/imager"},
    }
    for _, sample := range samples {
        fmt.Printf("%s → %s\n", sample.Path, removableName(sample.Mount, sample.Path))
    }
}

Likely false positives: path normalization can group legitimate field, installer, forensic, and diagnostic media with unknown media. Use the normalized path for joins, but make the decision with mount type, volume identity, hash, signer, user, and approved-use context.

Investigation checklist

  • Verify the mount is actually removable.
  • Confirm mount, file, and process timestamps.
  • Identify whether image or parent is the origin.
  • Verify hash and signer/package provenance.
  • Check user, shell history, child processes, and network activity.
  • Confirm business owner, ticket, and allowlist expiry.
  • Capture evidence before unmounting if policy permits.

Blind spots and limits

  • Execution after a copy to local disk needs a different rule.
  • In-memory execution may lack a stable file event.
  • Containers may expose host mounts under different paths.
  • Linux code-signing fields may be absent or enrichment-derived.
  • T1091 should not be claimed without replication evidence.
  • This behavior does not identify a specific actor or malware family.

Analyst reasoning and false positives

Approved field tools: require the registered volume, exact binary path, expected SHA-256, signer/provenance, assigned engineer, and valid work order. Software installers: confirm the deployment ticket and media owner; do not allowlist every executable on the volume. Forensic media: verify the response case, read-only controls, chain of custody, and tool hash. Vendor diagnostics: confirm the support window, vendor identity, exact script or binary, and destination systems. Any partial mismatch remains visible.

Do not label the event malicious from removable execution alone. Escalate with child processes, persistence, unusual network activity, user context, and file reputation.
