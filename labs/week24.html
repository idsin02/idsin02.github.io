Week 24 Â· Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Keep only IAM APIs that can grant permissions now.
  2. Parse the target, policy ARN, and policy document.
  3. Require an administrative action/resource delta.
  4. Suppress only exact approved platform or incident-response context.
  5. Return actor, target, source, user agent, policy, delta, and ticket.

Telemetry note

The query uses an AWSCloudTrail table plus four enrichment fields: ActorTeam, ApprovedChangeWindow, ChangeId, and normalized RequestParameters. Map these names to your connector and change-management enrichment.

A standalone CreatePolicy event creates a managed policy but does not grant it to a principal. This hunt keeps it visible for a separate policy-creation review but does not call it a grant.

KQL answer

Validation place: Microsoft Sentinel Logs or another Kusto workspace containing normalized CloudTrail and change-window enrichment.

let GrantEvents = dynamic([
  "AttachRolePolicy", "AttachUserPolicy", "AttachGroupPolicy",
  "PutRolePolicy", "PutUserPolicy", "PutGroupPolicy",
  "CreatePolicyVersion"
]);
AWSCloudTrail
| where EventSource == "iam.amazonaws.com"
| where EventName in (GrantEvents)
| extend Params = parse_json(RequestParameters)
| extend Target = coalesce(
    tostring(Params.roleName), tostring(Params.userName),
    tostring(Params.groupName), tostring(Params.policyName))
| extend PolicyArn = tostring(Params.policyArn),
         PolicyText = tostring(Params.policyDocument),
         SetAsDefault = tobool(Params.setAsDefault)
| extend GrantsNow = EventName != "CreatePolicyVersion" or SetAsDefault == true
| extend ManagedAdmin = PolicyArn =~ "arn:aws:iam::aws:policy/AdministratorAccess"
| extend InlineAllow = PolicyText matches regex @'(?i)"Effect"\s*:\s*"Allow"'
| extend BroadAction = PolicyText matches regex @'(?i)"Action"\s*:\s*("\*"|"iam:\*"|\[[^\]]*("\*"|"iam:\*")[^\]]*\])'
| extend BroadResource = PolicyText matches regex @'(?i)"Resource"\s*:\s*("\*"|\[[^\]]*"\*"[^\]]*\])'
| extend AdministrativeDelta = GrantsNow and (ManagedAdmin or (InlineAllow and BroadAction and BroadResource))
| extend ApprovedPlatform = ApprovedChangeWindow == true
    and ActorTeam =~ "platform-team"
    and ChangeId startswith "CHG-"
    and (UserAgent has "Terraform" or UserAgent has "CloudFormation")
| extend ApprovedIR = ApprovedChangeWindow == true
    and ActorTeam =~ "incident-response"
    and ChangeId startswith "INC-"
| where AdministrativeDelta and not(ApprovedPlatform or ApprovedIR)
| extend PrivilegeDelta = iff(ManagedAdmin, "+ AdministratorAccess", "+ broad IAM/admin actions on *")
| project EventTime, EventName, Actor=UserIdentityArn, Target,
          PolicyArn, PrivilegeDelta, SourceIPAddress, UserAgent,
          ActorTeam, ChangeId
| order by EventTime desc

Analyst reasoning and false positives

Likely false positives: approved platform-team changes, infrastructure-as-code deployments, and incident-response elevation. Do not suppress them by actor or tool alone. Require a valid time-bounded window, expected team, ticket pattern, approved user agent, target scope, and an owner. Also review CreatePolicy separately: a dangerous policy can be staged for later use even though creation alone does not grant it.

CrowdStrike CQL answer

#Vendor="aws" #event.module="cloudtrail" eventSource="iam.amazonaws.com"
| in(field=eventName, values=[
    "AttachRolePolicy", "AttachUserPolicy", "AttachGroupPolicy",
    "PutRolePolicy", "PutUserPolicy", "PutGroupPolicy",
    "CreatePolicyVersion"
  ])
| target := coalesce([
    requestParameters.roleName, requestParameters.userName,
    requestParameters.groupName, requestParameters.policyName
  ])
| policy_arn := requestParameters.policyArn
| policy_text := requestParameters.policyDocument
| grants_now := eventName!="CreatePolicyVersion" or requestParameters.setAsDefault=true
| managed_admin := policy_arn="arn:aws:iam::aws:policy/AdministratorAccess"
| inline_allow := policy_text=/"Effect"\s*:\s*"Allow"/i
| broad_action := policy_text=/"Action"\s*:\s*("\*"|"iam:\*"|\[[^\]]*("\*"|"iam:\*")[^\]]*\])/i
| broad_resource := policy_text=/"Resource"\s*:\s*("\*"|\[[^\]]*"\*"[^\]]*\])/i
| admin_delta := grants_now and (managed_admin or (inline_allow and broad_action and broad_resource))
| approved_platform := change.approved=true and change.actor_team="platform-team"
    and change.id=/^CHG-/ and userAgent=/(Terraform|CloudFormation)/i
| approved_ir := change.approved=true and change.actor_team="incident-response"
    and change.id=/^INC-/
| admin_delta=true and approved_platform!=true and approved_ir!=true
| privilege_delta := case {
    managed_admin=true | "+ AdministratorAccess";
    * | "+ broad IAM/admin actions on *";
  }
| select([@timestamp, eventName, userIdentity.arn, target, policy_arn,
          privilege_delta, sourceIPAddress, userAgent,
          change.actor_team, change.id])

Analyst reasoning and false positives

Likely false positives: platform engineers applying a reviewed Terraform plan, CloudFormation deployment roles, and incident responders using time-bound emergency access. Confirm the parser and fields, then preserve visibility when the source, target, user agent, ticket, team, or approved window differs.

Analyst reasoning and false positives

The rule detects a portable subset and deliberately omits standalone CreatePolicy, because that event does not grant the policy to a principal. Extract actions and resources with Python

What should be done

Sample policy.json

Python answer

import json


def as_list(value):
    return value if isinstance(value, list) else [value]


with open("policy.json", encoding="utf-8") as file:
    policy = json.load(file)

for statement in policy.get("Statement", []):
    if statement.get("Effect") != "Allow":
        continue

    actions = as_list(statement.get("Action", []))
    resources = as_list(statement.get("Resource", []))

    for action in actions:
        for resource in resources:
            print(f"{action} â†’ {resource}")

Why it is intentionally small

This lab teaches reliable extraction, not a full IAM authorization engine. Real evaluation also considers NotAction, NotResource, conditions, permission boundaries, service-control policies, session policies, and explicit denies.

What should be done

Go answer

package main

import (
    "encoding/json"
    "fmt"
    "os"
    "sort"
)

type Statement struct {
    Effect   string   `json:"Effect"`
    Action   []string `json:"Action"`
    Resource []string `json:"Resource"`
}

type Policy struct {
    Statement []Statement `json:"Statement"`
}

type Fixture struct {
    Before Policy `json:"before"`
    After  Policy `json:"after"`
}

func permissions(policy Policy) map[string]bool {
    result := map[string]bool{}
    for _, statement := range policy.Statement {
        if statement.Effect != "Allow" {
            continue
        }
        for _, action := range statement.Action {
            for _, resource := range statement.Resource {
                result[action+" â†’ "+resource] = true
            }
        }
    }
    return result
}

func main() {
    data, err := os.ReadFile("policy_diff.json")
    if err != nil {
        panic(err)
    }

    var fixture Fixture
    if err := json.Unmarshal(data, &fixture); err != nil {
        panic(err)
    }

    before := permissions(fixture.Before)
    after := permissions(fixture.After)
    added := []string{}

    for permission := range after {
        if !before[permission] {
            added = append(added, permission)
        }
    }

    sort.Strings(added)
    for _, permission := range added {
        fmt.Println("ADDED", permission)
    }
}

Analyst meaning

The first line is a strong administrative delta. The second is broad role-assumption capability; its impact depends on which roles trust the principal. The diff is more useful than merely reporting that a policy changed.
