Week 2 · Day 2

KQL behavior query + tuning

Page 3 / 8

What should be done

  1. Keep PowerShell images.
  2. Extract only a complete encoded-command token.
  3. Remove two exact approved parent contexts.
  4. Project image, command line, parent, signer/publisher, user, and device.

Why exact boundaries matter

A search for enc would hit encodedcommand.ps1, -Encoding, and quoted help text. The regex requires whitespace or a command boundary around a listed flag.

The short forms are intentionally enumerated. Expand the list only after testing the exact PowerShell version in your environment.

KQL answer

Validation place: Microsoft Defender Advanced Hunting. Confirm schema and expected fields with one known process event.

let EncodedFlagPattern = @"(?i)(?:^|\s)(-(?:e|ec|enc|enco|encodedcommand))(?:\s|$)";
DeviceProcessEvents
| where FileName in~ ("powershell.exe", "pwsh.exe")
| extend EncodedFlag = extract(EncodedFlagPattern, 1, ProcessCommandLine)
| where isnotempty(EncodedFlag)
| extend ApprovedDeployment =
    InitiatingProcessFolderPath =~ @"C:\Windows\CCM\CcmExec.exe"
    and InitiatingProcessVersionInfoCompanyName =~ "Microsoft Corporation"
    and AccountName =~ "SYSTEM"
| extend ApprovedSecurityTool =
    InitiatingProcessFolderPath =~ @"C:\Program Files\ContosoSec\Responder\responder.exe"
    and InitiatingProcessVersionInfoCompanyName =~ "Contoso Security LLC"
    and AccountName =~ "SYSTEM"
| where not(ApprovedDeployment or ApprovedSecurityTool)
| project Timestamp, DeviceName, AccountDomain, AccountName,
          FileName, FolderPath, ProcessCommandLine,
          ProcessVersionInfoCompanyName,
          InitiatingProcessFileName, InitiatingProcessFolderPath,
          InitiatingProcessVersionInfoCompanyName, EncodedFlag
| order by Timestamp desc

Analyst note

Likely false positives: software deployment wrappers, help-desk scripts, and sanctioned security tools. A production exclusion should bind multiple stable properties such as exact parent path, publisher/signer, service account, managed-device scope, owner, and expiry date. The example values are lab placeholders.

Week 2 · Day 5

Exact token extraction in Python

Page 6 / 8

What should be done

Save the Day 1 fixtures as events.jsonl. The program keeps quoted text together, strips only matching outer quotes, compares whole tokens, applies the two exact allowlists, and checks expected labels.

Substring traps to avoid

  • C:\Lab\encodedcommand.ps1
  • -Command "Write-Host '-enc'"
  • -Encoding utf8
  • help-encoded-command.txt
None of those strings is an encoded-command flag token.

Python answer

import json
import re

FLAGS = {"-e", "-ec", "-enc", "-enco", "-encodedcommand"}
TOKEN = re.compile(r'"[^"]*"|\'[^\']*\'|\S+')


def tokens(command_line):
    found = TOKEN.findall(command_line)
    return [
        item[1:-1] if len(item) >= 2 and item[0] == item[-1] and item[0] in "\"'" else item
        for item in found
    ]


def encoded_flag(command_line):
    for item in tokens(command_line):
        if item.lower() in FLAGS:
            return item
    return None


def allowed(event):
    parent = event["parent_image"].lower()
    user = event["user"].lower()
    parent_signer = event["parent_signer"].lower()
    deployment = (
        parent == r"c:\windows\ccm\ccmexec.exe"
        and user == r"nt authority\system"
        and parent_signer == "microsoft corporation"
    )
    security_tool = (
        parent == r"c:\program files\contososec\responder\responder.exe"
        and user == r"nt authority\system"
        and parent_signer == "contoso security llc"
    )
    return deployment or security_tool


def detect(event):
    image = event["image"].replace("\\", "/").split("/")[-1].lower()
    return (
        image in {"powershell.exe", "pwsh.exe"}
        and encoded_flag(event["command_line"]) is not None
        and not allowed(event)
    )


passed = 0
with open("events.jsonl", encoding="utf-8") as source:
    for line in source:
        event = json.loads(line)
        actual = detect(event)
        ok = actual == event["expected_match"]
        passed += ok
        flag = encoded_flag(event["command_line"]) or "none"
        print(event["event_number"], flag, "PASS" if ok else "FAIL")

print(f"{passed}/8 decisions passed")

The same token check in Go

Page 7 / 8

What should be done

Use one small regular expression to keep quoted text together, normalize only matching outer quotes, and compare lowercase whole tokens. Then prove the behavior with a table-driven test.

Arrow rendering check

The HTML source escapes angle brackets, so both directions display correctly and copy as plain text.

powershell.exe ---> -EncodedCommand
-EncodedCommand <--- powershell.exe

Go implementation

package main

import (
    "fmt"
    "regexp"
    "strings"
)

var tokenPattern = regexp.MustCompile(`"[^"]*"|'[^']*'|\S+`)
var flags = map[string]bool{
    "-e": true, "-ec": true, "-enc": true,
    "-enco": true, "-encodedcommand": true,
}

func commandTokens(commandLine string) []string {
    items := tokenPattern.FindAllString(commandLine, -1)
    for i, item := range items {
        if len(item) >= 2 && item[0] == item[len(item)-1] &&
            (item[0] == '\'' || item[0] == '"') {
            items[i] = item[1 : len(item)-1]
        }
    }
    return items
}

func encodedFlag(commandLine string) string {
    for _, item := range commandTokens(commandLine) {
        if flags[strings.ToLower(item)] {
            return item
        }
    }
    return ""
}

func main() {
    fmt.Println(encodedFlag(`powershell.exe -EncodedCommand SQBFAFgA`))
}

Small table-driven test

package main

import "testing"

func TestEncodedFlag(t *testing.T) {
    tests := []struct {
        name string
        line string
        want string
    }{
        {"long flag", `powershell.exe -EncodedCommand SQBFAFgA`, "-EncodedCommand"},
        {"short flag", `pwsh.exe -enc JAB4AD0A`, "-enc"},
        {"case insensitive", `powershell.exe -E VwByAGkA`, "-E"},
        {"filename substring", `powershell.exe -File C:\Lab\encodedcommand.ps1`, ""},
        {"quoted script text", `powershell.exe -Command "Write-Host '-enc'"`, ""},
        {"ordinary script", `powershell.exe -ExecutionPolicy Bypass -File C:\HelpDesk\collect.ps1`, ""},
    }

    for _, test := range tests {
        t.Run(test.name, func(t *testing.T) {
            if got := encodedFlag(test.line); got != test.want {
                t.Fatalf("encodedFlag() = %q, want %q", got, test.want)
            }
        })
    }
}

Investigation sequence

  1. Confirm image path and signer/publisher.
  2. Confirm the exact encoded flag and capture the following token.
  3. Review parent, user, device role, and nearby process/network activity.
  4. Decode only in a controlled analyst environment.
  5. Treat decoded content as evidence to assess, not proof by itself.

Analyst notes: likely false positives

Deployment wrappers

Verify exact parent path, publisher/signer, package owner, service account, target group, change ticket, and expiry.

Help-desk scripts

Verify ticket, operator, affected device, script source, command line, expected encoded payload, and limited duration.

Sanctioned security tools

Verify tool identity, signed parent, tenant owner, approved response workflow, device scope, and version.

Decoding and optional YARA

Decoding is an investigation step, not a verdict. Preserve the original encoded token, record the decoder and encoding assumption, hash any saved output, and inspect it safely. YARA is optional only when the decoded script or payload is saved as a file. If no artifact is saved, keep this as a process-telemetry hunt and do not create a YARA rule.

Never execute decoded content to “see what it does” on an analyst workstation.
